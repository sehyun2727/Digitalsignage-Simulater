## 1. ユーザー視点の変更まとめ (ja)

### 1-1. サイネージのコピー・貼り付け (NEW)

- サイネージを選んだ状態で **「コピー」 → 「貼り付け」** ボタン、または **Ctrl+C / Ctrl+V**
  でサイネージを複製できます。
- 複製される項目: 種類、位置・サイズ・回転、パース (遠近法)、画面コンテンツ、表示設定、
  見た目の設定、接地シャドウ、環境なじませ、マスク。
- 貼り付け時に位置が少しずれ、新しいサイネージが自動的に選択されます。
- 複製は Undo/Redo の対象です。
- テキスト入力中の Ctrl+C/V は、通常どおり文字のコピーに使われます。

### 1-2. 縦横比を固定

- 幅・高さ入力欄の横に **🔗 (縦横比を固定)** ボタン。ON 状態で片方を変更すると、
  比率を保ったままもう片方が自動調整されます。
- Undo/Redo で ON/OFF 状態と幅・高さが同時に戻ります。

### 1-3. 設置場所の写真の表示方法

- 既定は **全体表示 (Fit)** — 写真全体をキャンバスに収めます。
- **画面いっぱい表示 (Cover)** に切り替え可能。Cover 時は「写真の一部が切れて表示される
  場合があります」と注意表示が出ます。
- 切り替えは Undo の対象、PNG と動画の書き出しにも同じ表示方法が反映されます。

### 2-1. キャンバスの自動フィット

- 100% 表示で 16:9 / 9:16 両プリセットがウィンドウ内に収まるよう自動調整。
- 書き出し解像度は常に 1920×1080 (横) または 1080×1920 (縦) — ウィンドウサイズと独立。

### 2-2 ~ 2-5. 右側パネルの改善

- 設定パネルは折り畳み (アコーディオン) 形式。必要なセクションだけ開いて使えます。
- 詳細設定は右パネル内の折り畳みに統合され、中央モーダル は消えました。
- 「書き出し」ボタン (PNG / 動画) は結果表示の下に大きく常時表示。
- エラーメッセージは 16 px 以上の読める大きさで、原因と解決策を 2 行表示。
  読み上げソフトにも対応 (`role="alert"`)。

### 3-x. 編集操作の改善

- **位置・サイズの詳細設定** は「選択中のサイネージ」内の折り畳み。初期は閉じ、
  サイネージを切り替えても開閉状態が維持されます。
- **アップロード条件** (ファイル形式、容量、解像度、動画秒数) をアップロードボタンの
  横に常時表示。
- **スライダーの現在値** を数値で表示 (例: 明るさ 60 %)。
  「暖色・寒色トーン」は符号付き (例: +25 / 0 / -30)。
- **コンテンツ拡大率** を 50 / 100 / 150 % のパーセンテージ表示に統一 (**50 % まで
  縮小可能** — v2-P3)。
- **マスク機能** を「手前の物で隠す (マスク)」に改名。4 点を指定すると、その場で
  「適用 / キャンセル」が表示 (詳細設定を開き直す必要なし)。ステップ①/②/③ の
  進行ガイド付き。

### 4-x. 用語の更新

- 空間 → **設置場所の写真**
- X 座標・Y 座標 → **横位置・縦位置**
- 外観 → **サイネージ外観の調整**
- レンダリングプリセット → **明るさ** (素材スライダー側は「画面の明るさ」に分離)
- モザイク → **手前の物で隠す (マスク)**
- LCD → **LCD (液晶)**
- 使い方関連の表示を **使い方ガイド** に統一 (ボタン・モーダルタイトル・フッター 📖
  すべて同じ表記)

### 5-x. 不具合修正

- 画像サイズ超過などで出たエラーは、正しいファイルを選び直すと自動で消えます。
- サイズ変更 → パース変更 → コンテンツ適用 の順でも、他の順序でも結果が同じになります。
  (パース中は幅・高さ入力が無効化され、角のハンドルで調整します。)

## 1-ko. 변경 요약 (한국어)

- **복사·붙여넣기** (버튼 / Ctrl+C+V): 종류·크기·회전·원근·콘텐츠·외관·그림자 등 모든
  설정을 포함해 복제. Undo/Redo 가능. 텍스트 입력 중에는 일반 복사·붙여넣기가 우선.
- **비율 고정 🔗**: 폭·높이 입력 옆에 토글. ON 상태에서 한쪽을 바꾸면 다른 쪽이 비례
  자동 조정. Undo/Redo 로 상태 복원.
- **설치 장소 사진 표시 방식**: 기본 전체 표시(Fit). 화면 꽉 채우기(Cover) 로 전환
  가능. Cover 시 안내 표시.
- **설정 패널 아코디언**: 필요한 섹션만 펼침. 상세 설정은 오른쪽 패널 안으로 통합.
- **에러 메시지**: 16 px 이상, WCAG AA 대비, 원인 + 해결 방법 2 줄.
- **콘텐츠 확대 비율**: 50 / 100 / 150 % 표기 — v2-P3 에서 **50 % 축소까지** 가능.
- **마스크**: 「앞쪽 물체로 가리기 (마스크)」 로 명칭 변경. 자리에서 바로 적용/취소.
  단계 ①/②/③ 안내.
- **용어**: 공간 → 설치 장소 사진, 외관 → 사이니지 외관 조정, 모자이크 → 앞쪽 물체로
  가리기(마스크), LCD → LCD(액정), 사이네지 → **사이니지** 통일.

## 4. 利用規約 (ToS) の日付設定

**単一の設定ファイル**: `src/lib/termsOfServiceDate.ts`

```ts
export const TOS_EFFECTIVE_DATE = '2026/9/28'; // v2-release 時点
export const TOS_REVISED_DATE = ''; // 空 = 行を非表示
```

- 発効日・改定日が決まったら、**この 2 行だけ** 書き換えて `npm run build:oitemiru` を
  実行し、本番にアップロードし直してください。
- フォーマットは自由ですが、ja ロケールで「2026年10月16日」、ko で「2026년 10월
  16일」、en で「October 16, 2026」のように自然な表記を推奨します。
- 空文字 (`''`) の場合、`termsOfServiceEffectiveDate` / `termsOfServiceRevisedDate` の
  行自体が利用規約モーダルから **隠されます** (旧実装の「2026年月日」のような壊れた表記は
  出ません)。
- 片方だけ値を入れることも可能 (例: 初回公開時は改定日なし → `TOS_REVISED_DATE = ''`)。

### 4-1. 設定例

ja ロケールで `2026年10月16日` にしたい場合、`TOS_EFFECTIVE_DATE = '2026年10月16日'`
のように設定します。ロケール側のテンプレートは `制定日：{date}` / `제정일: {date}` /
`Effective date: {date}` となっており、`{date}` が差し替えられます。

**3 ロケール共通で同じ文字列を使うか、ja/ko/en それぞれ適した表記にするか** は運用判断ですが、
現在の実装は 3 ロケール共通です (将来 locale-specific にしたい場合は
`src/lib/termsOfServiceDate.ts` を 3 変数に分割)。

## 4b. v2-release 承認事項詳細 (D11 + D12 + Linux goldens)

### D11 — canvas-freeze baseline プラットフォーム分離 (approved-by-user 2026-10-17)

**背景**: PR #2 CI 最初実行 (run 38943078815) で canvas-freeze が 4 シナリオ失敗。原因は `docs/v2/canvas-freeze.json` の baseline が Win32 ローカル測定値のまま commit されており、Linux CI (Ubuntu Chromium) の shell font metrics + mobile breakpoint 計算が異なるため small-viewport 以下で 0.8-5.6 px の systematic drift が出ることだった。push CI は e2e をスキップ (ci.yml:75) するため、PR CI で初めて露呈。

**変更内容**: scenario ごとに optional `linuxOverride: { x, y, width, height }` を追加。`e2e/canvas-freeze.spec.ts` が `process.platform === 'linux'` で `linuxOverride` を、それ以外 (`'win32'`, `'darwin'`) で top-level values を選択。他 6 シナリオ (1920×1080 + 1440×900 + 1280×720 の landscape/portrait) は両プラットフォーム一致で `linuxOverride` 不要。許容値 `tolerance_px: 0.5` は変更なし — シナリオ削除も許容値緩和もしていない。
