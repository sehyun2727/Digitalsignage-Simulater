# Test fixtures: no committed photo/video assets

This directory intentionally has no binary fixture files (no `.png`/`.jpg`/`.mp4` committed to the
repo for tests). Every "photo" and "video" used across `e2e/` — including the Sprint 4.8
"real-photo-style" golden-image scenarios in `e2e/visual-qa.spec.ts` (bright interior, dark
interior, outdoor daylight) — is generated procedurally at test time, in the browser, via
`<canvas>` drawing:

- `e2e/support/spaceBackground.ts`'s `solidColorPng()` (flat color fills) and `scenePhotoPng()`
  (gradients + radial highlights simulating window light, dim ambient interior lighting, and
  sky/sun daylight) both draw to an in-page `<canvas>` and export it via `toDataURL('image/png')`.
- `e2e/support/video.ts`'s `generateWebmVideo()` follows the same pattern using
  `canvas.captureStream()` + `MediaRecorder`.

## Why

- **License-clean by construction:** every pixel is generated by code in this repository, so there
  is no third-party photo/stock-asset licensing to track or attribute.
- **No network fetches in tests:** fixtures never depend on downloading an external image, keeping
  the suite deterministic and runnable offline/in CI without egress.
- **Consistent with the project's existing convention:** this is not a new pattern introduced for
  Sprint 4.8 — it reuses the exact in-browser generation approach already established by
  `solidColorPng()`/`generateWebmVideo()` for every other spec in this suite.

`scenePhotoPng()`'s output is a synthetic stand-in for a real interior/exterior photo (gradients,
not a photograph) — good enough to give the golden-image scenarios a non-flat, busier background
to render shadow/glow/material effects against, but it is not, and is not meant to be, a
photorealistic image. If a future sprint needs coverage against an actual photograph, that would
require sourcing a CC0/license-clean image, committing it here, and documenting its provenance in
this file — not silently swapping it in.
